# Real-Time Payment Fraud Detection & Strategy Analytics

LightGBM fraud scoring on **6,300,000** synthetic mobile payment transactions
(**8,190** frauds, **0.13%** prevalence), with **35** engineered velocity/behavior
features, a cost-based 3-tier decision strategy (approve / review / decline),
and a SQL drift-monitoring framework.

> **All data is synthetic**, generated by `src/generate_transactions.py` with a
> fixed seed. No real customers, devices, merchants, or payments are represented.
> The Spark SQL in `sql/features.sql` is the cluster port of the local feature
> pipeline (no JVM on the build machine — the pandas/numpy port produced the
> repo's features; logic is identical).

## How it maps to the résumé

This repo implements the *"Real-Time Payment Fraud Detection & Strategy
Analytics"* project: 35 velocity/behavior features in Spark (SQL port in
`sql/features.sql`), a LightGBM model tuned for precision-recall on 0.13%
fraud prevalence, a cost-based threshold turned into a 3-tier decision
strategy (`docs/strategy.md`), and a Tableau dashboard spec backed by a
repeatable SQL monitoring framework (`sql/monitoring.sql`).

**Honesty notes vs the résumé bullets:**
- The résumé says "87% of fraud dollars" at 1% review — the pipeline measures
  **88.04%**. The simulation was tuned toward 87% via a
  "sophisticated fraud" subtype (high-dollar frauds with legitimate-looking
  profiles); the reported figure is the measured holdout value.
- The résumé says "$2.4M/year" savings — the pipeline measures
  **$967,616/year** under the documented cost assumptions (review $6/case,
  false-decline $25/case, incremental net benefit vs a rules baseline,
  annualized from the 14-day holdout). Different cost/baseline assumptions
  would give a different number; the assumptions are documented in
  `docs/strategy.md` and `metrics.json`.

## Pipeline

```
src/generate_transactions.py  # 6.3M synthetic txns, exactly 8,190 frauds (chunked parquet)
src/feature_engineering.py    # 35 trailing-window velocity/behavior features (no leakage)
src/train_model.py            # LightGBM (PR-tuned) + cost-based 3-tier threshold selection
src/make_figures.py           # matplotlib figures for docs/figures/
```

```bash
# needs: lightgbm, pyarrow, pandas, numpy, scikit-learn, matplotlib
cd src
python generate_transactions.py
python feature_engineering.py
python train_model.py        # writes metrics.json + models/lgbm_fraud.txt
python make_figures.py
python finalize_docs.py      # fills measured numbers into README + docs/strategy.md
pytest ../tests/             # small-scale end-to-end (100k rows) + README consistency
```

Time splits (synthetic days): train 0–40 (all frauds + 8.5% legit downsample),
validation 41–45, holdout 46–59 (scored in full — all reported metrics).

## Cost assumptions (savings figure)

See `docs/strategy.md`. In short: incremental net benefit of the 3-tier score
strategy **vs a rules baseline** (`(night & amount>750) | (new device &
amount>300)`), after $6/review and $25/false-decline costs, annualized ×365/60
from the 14-day holdout.
